# RGV587 · что делать

## Симптом

Поиск Goofish работает, а `goofish_item` / `goofish_seller` / `goofish_reviews`
возвращают `FAIL_SYS_USER_VALIDATE; RGV587_ERROR::SM::哎哟喂,被挤爆啦`.
Иногда браузер вместо карточки показывает «为你推荐».

Это риск-контроль Alibaba: аккаунт/IP временно ограничен после серии запросов.
Капчу нельзя решать автоматически; смена VPN/cookie помогает не всегда.

## Что уже сделано (Фаза 1)

- классификатор `src/goofish/errors.js`: RATE_LIMIT, NEEDS_VERIFICATION,
  SESSION_EXPIRED, TOKEN_REFRESHABLE, TRANSIENT_NETWORK, NOT_FOUND;
- пул аккаунтов `src/goofish/accounts.js` с отдельными cooldown для карточек
  и поиска: RGV на карточке не блокирует поиск;
- эскалация: 30 мин за первый страйк, 24 ч за второй; сброс после успеха;
- дневной лимит, TTL-кэш карточек/поиска/профилей/отзывов;
- режим search-only: если карточки недоступны, бот отдаёт 3 лота из поиска
  с пометкой «проверить», без ложного «брать»;
- команды `/accounts`, `/cookie`, `/verify_help`;
- `npm run probe -- health` и `data/health.json`.

## Что делать при блоке

1. Не повторять запросы. Подождать 30–120 минут; при повторе cooldown растёт.
2. Открыть goofish.com в браузере, пройти капчу/слайдер, открыть карточку.
3. Обновить cookie из браузера и отправить боту `/cookie <cookie>`.
4. Проверить `/accounts`: статус `ok`, карточки доступны.
5. Если не помогает — другой аккаунт (`GOOFISH_ACCOUNTS`) или резидентный прокси.

## Диагностика

    npm run probe -- health
    npm run probe -- item 1092149222408
    npm run probe -- search 小米13Ultra

На ошибке probe пишет `data/health.json` с kind/code/retry_after и health.

## Ограничения

- Автоматическое решение капчи запрещено.
- Пул из одного аккаунта не спасает от блокировки IP/аккаунта.
- Search-only не заменяет проверку карточки, продавца и фото.
